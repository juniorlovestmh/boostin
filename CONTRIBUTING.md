# Contributing

Use GitHub Issues and the configured triage labels. Create normal work on a
short-lived `dev/*` branch from `staging`, then open a pull request back to
`staging`. Release candidates move from `staging` to `main` by pull request.
Do not commit feature work directly to `main` or `staging`.

Use Node 22 and pnpm 11.7.0. The repository's `.node-version` and
`packageManager` fields match the versions used by Verify.

Hard boundaries:

- Never submit a real social-network export, analytics workbook, database,
  private report, account identifier, credential, or private screenshot.
- Reproduce import problems with `boostin doctor --fingerprint` and synthetic
  fixtures generated by `pnpm fixtures:generate -- --out <directory>`. This
  writes a synthetic post archive and matching analytics workbook; neither
  contains real account or content data.
- Pull requests adding scraping, browser control, auto-posting, automated
  comments or reactions, connections, messages, outreach, or contact graphs
  will be closed as out of scope.

Run `pnpm validate` before opening a pull request.
